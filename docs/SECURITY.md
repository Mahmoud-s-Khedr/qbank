# Security

Qbank protects school accounts, question banks, workbook uploads, generated exams, and OpenRouter credentials. Actors include unauthenticated internet clients, authenticated teachers and editors, organization administrators, operators, and the external LLM and object-storage providers. Trust boundaries include the browser/API boundary, the Caddy/API proxy boundary, organization-scoped database access, the API/worker and storage boundaries, and requests to OpenRouter.

Controls include Argon2 password hashing, minimum password length and a bundled common-password denylist (the first 1,000 case-insensitively distinct entries in [SecLists Pwdb](https://github.com/danielmiessler/SecLists/blob/master/Passwords/Common-Credentials/Pwdb_top-10000.txt)), HTTP-only secure production session cookies, CSRF tokens, organization scoping, role checks, versioned session revocation, Redis rate limits, and bounded uploads with PDF signature and encryption checks. Credentials are supplied through environment variables. The production network publishes only Caddy, and forwarded client IPs are trusted only from its configured internal address. Deploy behind any additional proxy only after configuring and reviewing the trusted chain. Redis unavailability prevents rate-limited actions rather than silently disabling limits.

The API sets security headers and Caddy sets a restrictive content security policy. `style-src 'unsafe-inline'` permits KaTeX's generated inline styles; scripts are restricted to the same origin. Local storage resolves keys beneath its root. QMD export replaces external image URLs with a missing-figure placeholder rather than fetching them, and SQL is parameterized. Access logs omit request bodies, query strings, cookies and credentials; worker outcome logs do not record message bodies. Restrict log access and retention. LLM providers receive page images and prompts needed for extraction; school operators must assess their provider's privacy terms.

Limitations: rate limiting is not a substitute for monitoring, MFA, or incident response; MFA is not implemented. Redis loss resets counters. Local object storage and backups require filesystem protection. Uploaded PDFs and model output are untrusted; keep dependencies patched and use isolated, least-privilege infrastructure. Bundled MinIO uses root credentials for the application; an external S3 deployment should use a least-privilege account. The browser export uses Chromium and requires a working sandbox unless an operator deliberately disables it. Readiness is a reachability signal, not a backup or data-integrity check.

Report suspected vulnerabilities privately to the operator of your Qbank installation; do not post credentials, student data, or exploit details in public issues. Include affected version, reproduction steps, and a secure contact method. Rotate potentially exposed credentials and preserve relevant logs during response.
