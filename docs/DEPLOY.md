# Production deployment

A small school can start with a 4-vCPU, 8-GB RAM VPS and at least 50 GB of SSD storage; PDF volume, concurrency, browser exports, and backups can require more. Install Docker Engine, the Compose plugin and GNU Make. Allow inbound TCP 80 and 443, point the domain's A/AAAA records at the VPS, and keep the host patched. HTTPS certificates are managed by Caddy. For localhost Caddy uses its internal CA; use `curl -k` only for local testing.

Copy `.env.prod.example` to `.env.prod`, restrict it with `chmod 600`, and set `QBANK_DOMAIN`, `POSTGRES_PASSWORD`, `QBANK_JWT_SECRET`, S3 credentials, and `QBANK_OPENROUTER_API_KEY`. Generate independent secrets using `python -c 'import secrets; print(secrets.token_urlsafe(48))'`; use URL-safe characters for the database password. Set a provider-side spending limit on the OpenRouter key, choose `QBANK_LLM_BUDGET_USD` (per source), and configure `llm_monthly_cap_usd` in each organization's settings. Review the model price limits, upload/page caps, and concurrency before use.

The example enables bundled MinIO. For external S3, remove `COMPOSE_PROFILES=minio`, set `QBANK_S3_ENDPOINT_URL`, bucket and credentials, and create the bucket before startup. The backend must have permission to read, write, list and delete objects. The fixed internal subnet `172.29.25.0/24` isolates services and identifies Caddy as the only trusted forwarding proxy; the dynamic address pool starts at .128 so Caddy's .2 address stays reserved. Change the subnet, pool, Caddy IP, trusted IP, and Uvicorn forwarded-allow IP together if they conflict with your network. No backend, database, Redis or MinIO ports are published.

Run `make prod-up`. It builds the images and waits for health checks; the one-shot migration runs before the API and worker. Create the first administrator with `make prod-admin ARGS='--org School --email admin@example.org --password YOUR_LONG_RANDOM_PASSWORD'`. Avoid recording the command or password in shell history or logs. Check `https://your-domain/api/v1/ready` and `make prod-logs`; `/api/v1/health` is the existing liveness check.

Back up with `make prod-backup`; this writes a compressed PostgreSQL dump under `backups/`. Back up the MinIO volume or external S3 bucket separately and securely; database backups alone cannot restore PDFs and figures. Test restores regularly. To restore a dump into a clean, stopped application database, start PostgreSQL, then run `gzip -dc backups/FILE.sql.gz | docker compose --env-file .env.prod -f docker-compose.prod.yml exec -T postgres psql -U qbank qbank`; restore the matching object-store snapshot as well. Restrict backup access and store encrypted copies off-host.

For upgrades, back up both stores, pull the reviewed release, then run `make prod-build` and `make prod-up`; migrations run automatically. Scale with `WORKER_REPLICAS`, `WORKER_PROCESSES`, and `WORKER_THREADS` in `.env.prod`, then run `make prod-up`. More workers can increase memory use and OpenRouter spending. `make prod-down` stops the stack without deleting volumes; `make prod-down ARGS=-v` also deletes local database, object storage, and Caddy volumes and is intended only for disposable installations.

If readiness is down, inspect `make prod-logs`, verify the database and Redis health, S3 endpoint and credentials, and bucket existence. If certificates fail, verify DNS, ports 80/443 and the domain. `CADDY_HTTP_PORT` and `CADDY_HTTPS_PORT` allow alternate host ports for local tests; public automatic certificate issuance normally requires 80 and 443. For a localhost test, use a disposable `.env.prod`, then `QBANK_DOMAIN=localhost make prod-up`, `curl -k https://localhost/`, `curl -k https://localhost/api/v1/ready`, and `make prod-down ARGS=-v`.
