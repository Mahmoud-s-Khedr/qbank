# T24 — End-to-end tests (Playwright) of the full flow, run in CI

**Owner:** Claude Code sub-agent (Sonnet 5.5) · **Branch:** `task/T24` · **Refs:** SPEC §4 (acceptance) · ARCHITECTURE §8 (e2e job) · AGENTS.md

## Goal
One automated browser test proves the product works end to end: upload a workbook → extraction → review → bank → exam → versions → PDF + DOCX downloads.
It runs in CI on every push, **without any paid LLM calls and without the copyrighted sample workbooks**.

## Scope
`frontend/e2e/**` (new), `frontend/package.json` (dev deps + scripts), `frontend/playwright.config.ts` (new), `backend/**` (only the scripted-fake LLM mode and the small API addition below),
`.github/workflows/ci.yml` (the new `e2e` job, added to the `all-green` needs), `Makefile` (`e2e` targets) and `scripts/e2e/**`.
Another task (T25) is editing backend security code in parallel, and T17 the bank UI. Keep your backend changes minimal and isolated.

## Requirements
### 1. Deterministic fake LLM for e2e (backend)
- `QBANK_LLM_MODE=fake` + `QBANK_LLM_FAKE_SCRIPT=<path to JSON>`: `get_llm_client()` returns a `FakeLLMClient` preloaded from that file,
  `{stage: [response, …]}`, where each response is the JSON the schema expects (`PageExtraction` for extract, a `Verification`, a classify batch, a `ComposePlan` + `ComposeSelection`).
  The queues should **repeat the last item** when they're exhausted (instead of raising), so retries and extra pages don't crash e2e. The guards still apply. Unit-test the loader.
- `scripts/e2e/make_fixture.py`: **generates a synthetic 2-page Arabic workbook PDF** (PyMuPDF: an Arabic title, 6 MCQs including one with a drawn rectangle as a figure, and one passage with 2 questions; use the Noto Naskh font from `backend/src/qbank/export/vendor/`).
  It also writes the matching fake script `scripts/e2e/fake_llm.json`, whose boxes match the generated layout (compute them from the positions you draw at). Commit both outputs (`scripts/e2e/workbook.pdf` and `fake_llm.json`). They're synthetic, so they're safe to publish.
- **API addition** (needed by the exam list): `ExamSummary` gets `versions_count: int` and `has_stale_versions: bool`. Add a test. Then make the T20 exam list (`frontend/src/features/exams/exams-page.tsx`) show a versions column with the stale badge (a small UI change; keep the existing tests green).

### 2. Playwright suite (`frontend/e2e/full-flow.spec.ts`)
`@playwright/test`, Chromium only, `baseURL` from env, traces and screenshots on failure, `ar` locale. Steps:
1. As the editor (seeded via `python -m qbank.cli seed-dev`): log in → Sources → upload `scripts/e2e/workbook.pdf` to the Biology subject → watch the live progress until **ready**.
2. Open Review → the queue shows the questions → open one → check the page canvas shows boxes → edit a stem (save) → approve all via bulk select (force-approve as admin if any have error issues: log in as admin for this step if needed).
3. Bank → search an Arabic word **without tashkeel** that appears in the stem **with tashkeel** → the result appears → open the detail drawer.
4. As the teacher: Exams → create exam → add 3 questions from the bank tab → a blueprint row adding 2 more → AI assistant prompt (the fake compose returns a proposal) → apply.
   Settings: the school name + Arabic-Indic digits. Versions & export: generate 2 versions → export the exam PDF + answer key PDF + exam DOCX for version A → wait for ready → **download each** and assert the content type, a non-empty body, and that the PDF starts with `%PDF` and the DOCX is a zip.
5. Edit the exam (change points) → the export shows **stale**.
Use roles and labels (`getByRole`) rather than CSS selectors. If an element lacks an accessible name, fix the UI (add a label) instead of using brittle selectors.

### 3. Running it
- `make e2e`: brings up infra, migrates a fresh `qbank_e2e` DB, seeds, starts the API (port 18000) and worker with the fake LLM env, builds the frontend and serves it via `vite preview` with an `/api` proxy (port 14173), runs Playwright, then tears down. A script `scripts/e2e/run.sh` handles the process lifecycle (always clean up, even on failure).
- **CI job `e2e`** in `ci.yml`: Postgres/Redis service containers + MinIO (or `QBANK_STORAGE_BACKEND=local`), uv + pnpm setup, Playwright browser install (cached), run `scripts/e2e/run.sh`, and upload the Playwright report as an artifact on failure. Add it to `all-green`'s `needs`.
- The whole e2e run takes ≤ 6 minutes in CI.
